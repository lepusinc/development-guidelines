# フィーチャーテストガイドライン

## 目的・対象領域

- HTTPリクエストや CLI コマンドの実行など、エンドツーエンドに近い経路でアプリケーション全体の挙動を対象とする。
- 目的は、ルーティング・ミドルウェア・コントローラ・DB を含めた実際のリクエスト〜レスポンスの流れ、またはコマンドの実行〜終了ステータス・副作用（DB更新・出力内容など）が、利用者の期待通りに動作することを保証すること。
- **[要修正]** 個々のロジックの分岐網羅や境界値検証はユニットテストに委譲し、フィーチャーテストではハッピーパスと主要な異常系（代表的なエラーレスポンスやコマンドの異常終了など）に絞って検証する。
