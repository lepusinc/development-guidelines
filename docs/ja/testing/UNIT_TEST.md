# ユニットテストガイドライン

## 目的・対象領域

- 関数・メソッド・クラスなど、最小単位のロジックを対象とする。
- 目的は、ロジックの分岐・境界値・異常系を高速かつ網羅的に検証すること。
- DB・HTTP・外部APIなど、プロセス外のリソースへの依存は最小限にする。依存が避けられない場合はモック・スタブに置き換える。
- 実行速度が速く、入力の組み合わせを大量に検証してもコストが小さいため、分岐・パターンの網羅性はユニットテスト側が担う。

## フォーマット・パースのテスト

CSVやAPIレスポンスなどのフォーマットをテストする場合はFixture を用意し、Fixture と一致するかをアサートする。

パースをテストする場合もFixture を用意し、Fixture を入力にする。
