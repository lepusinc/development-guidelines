# ドメインモデル（エンティティ）

このドキュメントでは、フレームワークに依存しない、エンティティ（状態を持つドメインのオブジェクト）の設計に関するガイドラインを定めます。Laravel の Eloquent モデルに固有のルールは、[Eloquent モデル](./laravel/ELOQUENT.md) にあります。

## 1. 状態とライフサイクル

状態の移り変わりは、アプリケーションの制御そのものです。どこからでも書き換えられると、ありえない状態や、付随する値の食い違いが生まれます。そのため、状態はエンティティ自身が守ります。

- **[厳守]** エンティティの状態（ステータス、結果、有効・無効のフラグなど、アプリケーションの制御に関わる値）は、エンティティの専用のメソッドからだけ変更できるようにする。サービス、コントローラー、画面の処理など、エンティティの外から状態の値を直接設定してはいけない。
- **[厳守]** 状態の変更に付随する値（依頼日時、確定日時、理由など）は、状態を変える専用のメソッドの引数としてだけ受け取る。付随する値を、別の setter や一括代入で設定できるようにしない。
- **[厳守]** 状態を変更できるかどうかの確認（今の状態から移れるか、前提を満たしているか）は、専用のメソッドの中で行う。変更できないときは、例外を投げる。
- **[要修正]** ある状態の変更に合わせて、子のエンティティの状態もそろえる必要がある場合は、親の専用のメソッドの中でそろえる。子の状態だけを、外から変えられるようにしない。
- **[要修正]** 永続化の都合で一括更新を使う場合も、その一括更新は専用のメソッドの中に閉じ込める。エンティティの外から、状態の列を直接一括更新してはいけない。

```text
// 悪い例：外から状態と付随する値を直接設定している
batch.status = IN_PROGRESS
batch.requestedAt = now()

// 良い例：専用のメソッドが、移れるかの確認と、付随する値の記録をまとめて行う
batch.markRequested(requestedAt = now())
```
