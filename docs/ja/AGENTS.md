# AIエージェントへの指示 - Lepus開発ガイドライン

`AGENTS.md`および`docs/`以下のマークダウンファイルは、AAIF（Agentic AI Foundation）のガイドラインに従って作成されています。

このリポジトリには、エンジニアリングチームのドキュメンテーション標準、レビューポリシー、およびPRテンプレートが含まれています。これは**ドキュメンテーション専用**であり、コードやビルド/テストの自動化は含まれていません。

## AIエージェント向けの主要な知識

### 1. リポジトリの目的と範囲

- **内部使用のみ**：Lepus Group外部からのPRは受け付けられません。
- すべてのコンテンツはドキュメンテーション用であり、コード実装用ではありません。
- 主要ファイル：`README.md`、`README.ja.md`、`CONTRIBUTING.md`、`docs/en/REVIEW_POLICY.md`、`docs/ja/REVIEW_POLICY.md`、`docs/en/ISSUE.md`、`docs/ja/ISSUE.md`、`docs/en/PULL_REQUEST.md`、`docs/ja/PULL_REQUEST.md`、`docs/en/GIT_WORKFLOW.md`、`docs/ja/GIT_WORKFLOW.md`、lepusinc/.github の PRテンプレート（<https://github.com/lepusinc/.github/tree/main/.github/PULL_REQUEST_TEMPLATE>）。

### 2. AIエージェントへのタスク委譲

- リサーチはリサーチ用サブエージェントに任せる。
- 設計は設計用サブエージェントに任せる。
- 実装は実装用サブエージェントに任せる。
- テストコードの作成はテストコード用サブエージェントに任せる。
- レビューはレビュー用サブエージェントに任せる。
- 計画（何を作るかを確定し、ユーザーの合意を得る工程）はメインエージェントが担う。ユーザーとの対話的なすり合わせが必要であり、バックグラウンドのサブエージェントには委譲できないため。

### 3. AIエージェントの精度向上プラクティス

- **不確実な時は推測せず確認する**：要件が曖昧、または情報が不足している場合、勝手に仮定せずユーザーに確認する。
- **現在のコードベースで裏取りする**：関数・ファイル・既存の挙動に関する主張は、それに基づいて行動する前に現在のコードで確認する。記憶や古くなっている可能性のあるドキュメントに頼らない。
- **仕様調査には DeepWiki/Devin MCP を活用する**：リポジトリの現在の仕様を調査する際、DeepWiki にそのリポジトリのインデックスがあれば DeepWiki MCP に問い合わせる。DeepWiki が対応していないプライベートリポジトリの場合は Devin MCP に問い合わせる。OSS・サードパーティ依存関係の仕様調査にも DeepWiki MCP を活用する。
- **レビュー/リサーチ結果を反証してから確定する**：レビューやリサーチの結果を確定報告する前に、独立した視点（別の反証パスなど）で疑わせ、false positive を減らす。
- **高リスク（L2）設計は複数案を比較する**：L2 相当の設計判断では、単一案に飛びつくのではなく、複数の独立した設計案を出してスコアリングしてから採用する。
- **コード編集には IDE の MCP を積極活用する**：JetBrains 製品などの IDE が MCP を提供している場合、クラス名変更などの構造的な編集にはそれを利用する。IDE のリファクタリング機能は参照箇所を自動で更新するため、エージェント自身が参照先を探し回る必要がなくなる。
- **コード編集後にフォーマッターを実行する**：コードフォーマッターが定められているプロジェクトでは、コード編集後にフォーマットを実行する。

### 4. パターンと規約

- **単一責任の原則**：バグ修正とリファクタリングは別々のPRにすべきです（ただし、最小限の、振る舞いを保持するリファクタリングは除く）。
- **RACIマトリックス**：開発者（実装/テスト）、レビューア/テックリード（品質/設計/リスク）、QA/PM（ACの定義/検証）。
- **バグ修正のためのテストファースト**：再現テスト→修正→リグレッションチェック。

### 5. ルールの重み付け（Severity Labels）

各ガイドラインのルールには以下の4段階のラベルが付いています。

| ラベル | 説明 |
| --- | --- |
| **[厳守]** | 原則として例外なし。このPR内で必ず修正すること。 |
| **[要修正]** | 修正必須。ただし、チケットを起票することで対応を遅延できる。（チケットURLまたはキーの明記が必要） |
| **[条件付き]** | 正当な理由があれば許容される。 |
| **[推奨]** | 必須ではないが、改善が望ましい。 |

### 6. 言語とドキュメンテーション

- すべてのドキュメントは英語（`docs/en/`）と日本語（`docs/ja/`）の両方で利用可能です。
- PRとレビューには、適切な言語バージョンを参照してください。
- 英語と日本語を併記する場合は、英語→日本語の順に記載してください。
